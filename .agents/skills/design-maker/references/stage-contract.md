# 设计图技能阶段契约

## 输入

- 当前有效需求与设计规则（复用现有 Spec/Design Brief、等价文件或明确用户决定）
- 用户提供的参考图、截图、品牌资产或原型资料

## 输出

可能输出：

- 设计方案
- 线框图
- 高保真原型说明
- 面向实现的 UI 注释

使用能降低开发不确定性的最小设计产物集合。

先按[项目设计读取流程](../../../../.creator/references/project-design.md)读取已采用规范及条件引用；按实际缺口选择工具与产物，不默认生成全页高保真图。只验证本次有效设计契约，不直接引用未采纳的库建议作为验收要求；原型不等于运行验证。

## 触发条件

只有满足至少一个条件时才启用：

- UI、布局、交互或品牌表达会显著影响开发计划。
- 用户需要在开发前检查关键页面或状态。
- 当前有效设计规则仍不足以让开发者判断本次界面结构。
- 目标项目需要对外部设计工具或视觉产物进行交接。

可以跳过的情况：

- 产品没有明显界面。
- UI 足够常规，开发计划可以直接拆分。
- 设计产物只会增加装饰，不减少风险。

## 最小设计产物

设计产物至少说明：

- 页面或流程清单
- 关键布局
- 空状态、加载状态、错误状态、成功状态
- 关键交互
- 响应式规则
- 与本次有效需求和设计规则的映射关系
- 留给开发阶段处理的细节

## 合格标准

设计产物必须：

- 覆盖本次范围中需要视觉决策的关键流程
- 包含重要空状态、加载状态、错误状态和成功状态
- 体现当前有效设计规则
- 能指导本次后续工作
- 不擅自扩展产品范围

## 必要未决项处理

- 必要页面、流程或风格仍未决：在本次范围补齐必要项，仅暂停依赖部分，独立部分继续。
- 当前设计产物只是视觉装饰、不能减少决策风险时跳过。

## 必须打回的情况

- 设计需要新增产品范围。
- 关键流程仍没有可确认的需求依据（同名 Spec 不是必要条件）。
- 当前有效材料与用户决定均不足以收敛必要体验选择；不因缺少同名 Design-Brief 文件打回。
- 用户要求高保真产物，但必要的品牌或体验边界仍未决；已有依据允许自主处理专业布局细节。

文档有效性、状态、证据与恢复统一遵循[共同契约](../../../../.creator/references/workflow-contract.md)的相关章节；仅加载本任务需要的部分。
