# 开发计划阶段契约

## 输入

- 可验收的 `Product-Spec.md`
- `Design-Brief.md` 或设计产物（如果相关）
- 现有仓库、脚本、测试和 CI 事实
- 0→1 或产品变更路线

## 输出

- **索引**：默认维护 `docs/DEV-PLAN.md`，保持简洁，只含状态总览、规则边界、当前 Phase 与 Phase 清单。
- **明细**：每个 Phase 的完整内容写入 `docs/dev-plan/phase-NN.md`（0→1 按顺序编号；产品变更按增量追加并标注变更 ID）。
- 0→1：完整 Phase 计划；产品变更：映射变更 ID 的增量 Phase，保留仍有效的已完成工作。

## 索引与明细结构

### 索引 `docs/DEV-PLAN.md`

```markdown
## 0. 执行状态总览   # 整体状态、当前 Phase、最近验证摘要
## 1. 规则边界       # 增量规范同步、验证门禁、部署授权
## 2. Phase 清单     # 每行一个 Phase：
# | Phase | 能力 | 状态 | REQ-AC 映射 | 验证命令 | 明细 | 完成证据摘要 |
```

- Phase 清单每行状态只使用：`未开始 / 进行中 / 已完成 / 已阻塞 / 已废弃`。
- **已完成 Phase 只读**：实现细节不改写，只在明细的“完成证据”区追加验证结果与审查结论。
- **计划削减**：在索引标 `已废弃` 并保留明细文件，不静默删除。
- **当前 Phase 之外不可变**：对已完成 Phase 的改动视为计划变更，新增 Phase 或变更记录承接，不直接改写历史。

### 明细 `docs/dev-plan/phase-NN.md`

```markdown
# Phase N：<可验收能力>
- 变更 ID / 关联（产品变更时）
### 目标
### 范围与非范围
### 依赖
### 任务与预期文件/产物
### 映射需求和验收标准
### 验证命令与交付证据
### R2 审查要求
### 完成证据（追加区）
```

**红线：明细必须保留完整任务与验证证据。** 归档或历史文件可以压缩成摘要，但不得用摘要替代明细文件；延续开发、验证与审查以明细为准。

## 范围声明生命周期

- **非目标 / 延期 / “先不管”是契约，不是永久承诺。** 写作时带基线锚点，写成自失效：
  `不新增站内搜索（Phase 1 基线；若后续承接，本声明作废并更新 Spec 对应章节）`。
- **范围对账**（每次切分或追加新 Phase 前执行）：扫描 Spec 与既有计划中与本次范围相关的非目标/延期/“先不管”声明，逐条三分：
  1. 仍成立 → 保持原样；
  2. 被本次承接 → 修订该声明，标记“由 Phase N 承接，本声明作废”，并把“更新 Product Spec 受影响章节”排进该 Phase 的任务；
  3. 承接但无变更记录 → **暂停**，返回 `product-spec-builder` 先记录产品变更，再回来规划。
- 对账结果写进索引或对应明细，供 reviewer 核验。

## 合格标准

- 索引可扫读，明细可执行：索引一行能定位明细文件与验证命令，明细不含占位符。
- 按可运行、可演示、可审查的能力切片。
- 每个 Phase 映射 `REQ-*` / `AC-*` 或产品变更 ID。
- 任务具体到文件、产物或可执行操作。
- 验证命令和证据足以判断通过或失败。
- 既有项目的技术栈与仓库事实一致。
- 用户决策、公开行为变化和高风险未知项没有被伪装成开发任务。
- 与本次范围相关的既有非目标/延期声明已对账，承接处已修订并排入任务。

## 必须打回

- 当前任务实际属于维护路线。
- Product Spec 或变更记录不可验收。
- 承接既有非目标/延期声明但无变更记录，却直接追加 Phase。
- Phase 无法独立运行、验证或审查。
- 依赖和影响范围不清。
- 已完成 Phase 的实现细节被无理由改写（已完成 Phase 只读，证据可追加）。
- 索引与明细缺失其一，或用摘要替代明细。
- 任务没有映射需求、变更 ID 或验收标准。

打回时说明不可验收范围、缺少的决策或证据，以及可先执行的最小 Phase（如果存在）。
