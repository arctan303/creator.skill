# 按证据区分根因

## 适用条件

根因未知、复现不稳定或偶现、首次修复无效，或症状可能不是原因时读取。明确堆栈已定位的简单错误可以直接修复，仍需相关验证；不强制重走调查。

## 短规则

- 先获得可靠复现；无法稳定复现时，选最有区分力的日志、状态或操作信号，记录触发条件和未知项。
- 比较正常与失败路径、输入和版本，找最早的差异；有可靠的已知正常基线时，可在隔离副本二分定位变更。
- 沿组件边界观察实际传入、返回的数据与状态，区分源头错误和下游表现，不凭最后一条报错定因。
- 一次验证一个能区分候选原因的假设：先写预期观测，再做最小检查，按结果保留或排除；没有新证据不重复试错。
- 在根因所在位置做最小完整修复，再按[验证方法](../../../../.creator/references/verification.md)检查原问题与相关回归。

## 错误 / 正确小例

错误：列表偶尔为空，就隐藏空状态或增加固定延时。

正确：比较成功与失败请求，在数据获取和状态提交边界观察顺序；用可控的乱序返回区分“无数据”和“旧响应覆盖”。证据确认后修正源头，再验证乱序与正常路径。

## 证据与例外

保留触发输入、基线、观测、假设和检查结果，区分事实、推断和未知。只有间接信号时说明限制；无法验证假设不宣称找到根因。相关有效契约仍未决时只暂停依赖部分，按既有路线处理，不用技术假设代替产品决定。
