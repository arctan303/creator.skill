# 设计规范技能阶段契约

## 输入

- 当前有效需求（Spec、等价文件或用户已明确决定）
- 0→1 产品或产品变更路线
- 用户的风格要求
- 用户提供的截图、品牌、竞品、参考产品或反例
- 项目已采用的设计入口及适用的逐层引用、有效例外、现有组件/tokens/素材；按[读取流程](../../../../.creator/references/project-design.md)核对。参考库裁切与已有规范合并遵循[适配流程](../../../../.creator/references/design-adaptation.md)。

## 输出

目标项目已有文档约定时遵循项目约定；没有约定时输出 `docs/Design-Brief.md`。兼容根目录旧文件，但不同时创建副本。

## 最小结构

建立完整设计规范时覆盖下列内容。局部任务只更新受影响的规则、依据、状态及验收点；不为补齐模板重写完整 Brief，不要求专门制图或 Phase。已经明确的方向无需另列虚构的弃选方案。

完整规范的参考结构：

- 设计目标和目标用户
- 使用环境和关键约束
- 已选视觉方向
- 被放弃的方向和原因
- 调性关键词及其具体解释
- 色彩、字体、间距、密度、布局和组件规则
- 每项关键规则的设计意图、理由、代价和验证检查点
- 对比度、非颜色状态提示、键盘/触控、字号和动效等可访问性约束
- 关键状态和响应式约束
- 用户提供的参考或反例
- 可观察的设计验收检查点

## 合格标准

本次更新的范围必须：

- 把主观审美转成具体设计决策
- 说明所选方向为什么适合产品
- 记录重要的被放弃方向
- 足以指导设计图或前端实现
- 包含可观察的设计验收检查点

## 主观词转换要求

遇到空泛审美词时，必须先结合任务、用户、内容、环境和品牌语境解释其含义，再转成可执行变量。不得把形容词直接绑定到固定配色、玻璃态、圆角、留白或字体风格。

示例：

- “高级感”必须落到明暗、留白、材质、字体、对比度、动效克制度等选择。
- “简洁”必须落到信息密度、层级数量、组件数量、默认状态和隐藏策略。
- “现代”必须落到布局节奏、字体气质、组件形态、动效和色彩策略。

多个专业实现合理不构成采访理由。先用已读项目规则、实际内容与页面任务收敛；只有必要未决取舍实质改变体验、费用、隐私或授权时，才询问有理由与代价的选择。截图或“简洁”等形容词本身不触发采访。

每个最终方向必须写成：`设计意图 → 决策 → 参数 → 理由/代价 → 验证检查点`。参考产品只拆解具体要素，不作为整套视觉皮肤。

## 退出条件

本次受影响的范围满足以下条件后可直接实施；制图与开发计划按任务需要选择：

- 视觉方向已被选择或有明确临时假设。
- 关键审美词已转成具体设计变量。
- 关键设计决策具有场景理由、代价和可观察检查点。
- 核心状态和可访问性约束已覆盖。
- 设计规则不扩大当前有效需求与本次授权范围。
- 后续设计或前端实现有可观察检查点。

## 必要问题与自主推进

先调查目标用户、环境和引用规范中可找到的事实，选择有依据的普通细节。冲突风格或未知用途只有使必要体验选择无法收敛时才需要提问；不存在这类阻碍时记录有限假设并继续。维护任务实际改变行为时纠正路由、更新相关契约，不因此自动重开采访。

控件、表面与保存方式依据项目有效决定；设计空白按已授权范围收敛并记录。本项目尚未采纳的库建议不能直接变成约束，库更新不触发重新设计；已有准则充分时可保留原样。不得借参考建议改变保存语义或把局部美化扩成品牌重做。

## 打回输出

确需提问时不要抛长问卷。简述：

- 已知产品和设计事实
- 当前无法落地的审美词或冲突
- 相关选择及具体代价
- 最多两个必要的体验问题；独立工作继续

文档有效性、状态、证据与恢复统一遵循[共同契约](../../../../.creator/references/workflow-contract.md)的相关章节；仅加载本任务需要的部分。
