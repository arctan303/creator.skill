# 通用设计基础：把场景转成项目规则

> 参考材料，未采纳不生效。本文只供设计适配阶段选择、裁剪和解释方案；日常开发读取项目已经采纳的设计准则，不直接继承本库。

本文适合缺少统一设计语言、已有组件混用，或需要把“清晰、紧凑、有质感”转成可验证选择的项目。
它不替代产品范围、品牌规范、原生平台规则或项目的有效例外；也不要求为一次局部修复重做视觉体系。
这里的默认建议是综合判断，不是某个设计系统共同规定的标准；行业名称不会自动决定配色、字体或页面结构。

## 先决定要帮助谁完成什么

适配时先拿一项真实任务、一组真实内容和一个有代表性的困难状态，比较方案是否帮助理解与操作。
“高级”可能指阅读的节奏，也可能指专业操作的稳定；不先理解场景便绑定大留白、低对比或玻璃效果会得出相反结果。
常见起点如下；采用哪一行取决于使用环境，同一产品可以有不同区域。

| 场景事实 | 可选方向 | 选择理由与代价 |
| --- | --- | --- |
| 每日反复核对同类信息 | 稳定对齐线、较高信息密度 | 减少扫视距离；仍需给错误、长值和目标区域留空间 |
| 偶尔完成一次的复杂任务 | 清楚分组、可见说明、逐步披露 | 减轻记忆负担；增加步骤需要真实依赖关系 |
| 长时间阅读和理解 | 稳定正文节奏、受控行宽、少打断 | 持续阅读更容易；不把操作后台的密度直接搬来 |
| 品牌展示和感知 | 内容主导的表达性排版、素材与节奏 | 可以更鲜明；仍需可读、可操作和可访问 |
| 大屏监控与远距离观看 | 大字号关键状态、清晰异常和时间范围 | 便于发现变化；不适合作为复杂编辑器的唯一布局 |

选定方向后，把结果写成项目自己的“意图 → 规则 → 参数 → 例外 → 检查点”，无需复制本章所有条目。
例如“紧凑”可以落成减少无意义容器、合并重复说明、保持同类值对齐，而不是缩小所有文字和点击区域。
必要的费用、权限、数据去向与恢复条件属于任务信息；不能以视觉精简为由移出决策位置。

## 信息关系决定结构

一个页面的起点是对象、当前状态和可完成的任务；标题先说清对象，不默认附加口号、欢迎词或指标卡。
默认以内容之间的关系选择布局，再决定是否需要边界；外框本身不能制造信息结构。

| 内容关系 | 可选表达 | 避免的误用 |
| --- | --- | --- |
| 一个对象的若干属性 | 描述列表或紧凑键值行 | 每个属性一张巨大等高卡片 |
| 同类对象需要比较 | 对齐的列表或表格 | 将比较字段分散到不同行高的卡片 |
| 异质模块或图片主导的浏览 | 有清楚范围的卡片 | 机械禁止卡片，或多层套卡片 |
| 可选的解释、少数人使用的细节 | 就近详情或帮助入口 | 隐藏多数人完成任务所需的信息 |
| 必须聚焦的短任务 | 有独立理由的模态区域 | 为几项普通设置增加重复的编辑弹窗 |

主操作的优先级来自任务，不是每个区域都分配一个强调色按钮。
危险操作可以与日常操作保持距离，同时保持可发现；“删除”不能只藏在无法辨认的图标里。
导航定位、独立区域标题和可访问名称中的必要重复应保留；同一事实的四种文案复述可以合并。
具体表单与数据场景可在适配时对照[表单与设置](forms-and-settings.md)及[后台与数据管理](admin-and-data.md)。

## 视觉尺度与共用资产

先盘点项目已经使用的组件、文字角色、间距、颜色语义、图标和素材；沿用有效体系比引入另一套皮肤更稳定。
同一角色保持一致不等于所有内容相同：正文、辅助说明、标题和代码值可以有不同角色，但各自需要一致的用途。
输入、选择、按钮显式使用对应文字角色；别依赖浏览器默认字体恰好与自绘组件一致。
标签与控件的距离表达归属，字段之间表达分隔，组之间表达主题变化；先用共享尺度，避免逐项补 margin。
长中文、长译文和 URL 需要可预期的换行或展开方式；不要用固定高度裁掉任务内容。

以下只是没有等价项目体系时的试验起点，采用后应变成项目语义变量，并以真实内容调整。

| 变量 | 可试起点 | 调整依据 |
| --- | --- | --- |
| 字体 | 现有字体；无约定时系统字体及中文回退 | 品牌、平台、字形覆盖、加载代价 |
| 正文与表单文字 | 16px / 24px 对应的相对单位 | 阅读距离、密度、缩放和内容长度 |
| 必要辅助文字 | 14px / 20px 对应的角色 | 对比度、译文、用户视力和平台惯例 |
| 间距阶梯 | 4、8、12、16、24、32 的有限组合 | 内容关系与实际控件，不是数字越多越完整 |
| 普通表单宽度 | 约 640px 的最大内容宽度 | 字段长度、宿主面板和窄屏空间 |
| 触控目标 | 优先尝试约 44×44 CSS px 或更大 | 手指操作、相邻目标和设备环境 |

圆角、阴影与颜色由品牌及表面职责决定；直角、深色或高密度都不是天然错误。
阴影可以区分浮层，边界可以标识输入，背景可以组织区域；不用同时给每层添加四种装饰。
焦点环、选中态和错误态承担行为信息；不能因为“更干净”删除这些差异。
图标优先复用项目现有资产，保持同类图标的尺寸、描边和位置；新增素材要有内容或识别价值。
新素材或字体的来源、授权、加载与隐私代价需要在项目中解决，本参考不授予下载、上传或发布权限。

## 状态与无障碍是设计的一部分

普通内容在等效 320 CSS px 宽度下重排是 WCAG 2.2 AA 的相关要求；真正依赖二维关系的表格等有明确例外。
二维例外属于相应区域，不意味着整页导航、说明与按钮也可以横向溢出；单元格内内容仍要可读。
文字对比度通常至少 4.5:1，大字号至少 3:1；大字号的定义与非活动、装饰、标志等例外按来源判断。
指针目标的 24×24 CSS px 下限及间距等例外，与 44×44 的更大触控目标不是同一个标准等级。
状态不能只靠颜色区分；补足文字、图形、位置或程序化语义，但不必同时堆叠所有信号。
异步成功、等待或失败的必要状态消息可由辅助技术感知；不把整张不断刷新的表格当作高优先级播报。
键盘顺序应与理解顺序相符；视觉换列后检查 DOM 和焦点，避免用户在页面两端来回跳跃。
动效的目的可以是解释关系或反馈变化；项目可采用减少动态效果的方案，不把一种动效风格通用化。

| 关键状态 | 可观察表现 | 容易掩盖的问题 |
| --- | --- | --- |
| 初次加载 | 说明正在获取什么，避免布局无规律跳动 | 不确定进度伪装成精确百分比 |
| 刷新已有内容 | 保留仍有价值的内容并交代更新时间 | 把旧数据显示为刚刚成功获取 |
| 为空或无结果 | 区分未创建与筛选后无结果 | 用户被错误引导重复创建 |
| 失败或无权限 | 说明事实及真实可行的下一步 | 把所有问题都写成字段输入错误 |
| 禁用或只读 | 在需要时说明限制来源 | 只有灰色，没有可理解的原因 |

## 反例与有意例外

- 反例：每个小标题都有彩色图标块与同义副标题。适配时保留帮助定位的部分，删减没有信息增量的装饰。
- 反例：为消除“AI 味”禁用某类字体、紫色或圆角。质量检查应回到任务、层级和内容，不把流行度当缺陷。
- 有意例外：作品集需要表现材料质感，卡片和大图有内容价值；不套用后台表格的密度。
- 有意例外：专业桌面工具采用较小行高，但需要真实目标尺寸、键盘和缩放证据，不能用“专家用户”免除可用性。
- 有意例外：原生宿主有既定控件与导航；采用平台惯例可以优先于本章的 Web 起点。

## 项目化例子与可观察验收

例：一个插件设置面板要呈现连接状态、五项字段及来源信息。采纳后，项目可规定“字段原位排列、保留 Save、来源以域名加可复制完整地址呈现”。
理由是降低重复编辑路径与扫视成本；代价是长错误会增加表单高度，因此控件列需要允许换行。
这不推导出改字段类型、自动保存、移除取消或把技术信息全部隐藏；这些仍由实际产品契约决定。

- 用真实长名称、中文错误及长 URL 检查整体与局部渲染，确认标题、控件和反馈的归属清楚。
- 在桌面、窄屏和放大状态完成相关任务，确认内容重排、目标可达且焦点可见。
- 键盘完成一次主要路径；查看成功、失败、空结果与禁用状态，不能仅凭默认截图判断。
- 自查项目规则是否写明采用范围、实际变量和例外；本参考写完只证明资料可用，不证明产品已经符合。

## 已核实的一手来源

核实日期：2026-11-11。以下来源支持对应原则；本文的场景表、参数起点与项目例子属于独立综合。

- [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/)：键值信息使用描述列表，并与表格、简单列表区分；不据此规定所有页面视觉。
- [GOV.UK Details](https://design-system.service.gov.uk/components/details/)：适合少数人需要的补充信息，不能隐藏多数人所需内容。
- [WCAG 2.2：对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[目标大小](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：核对相关 AA 阈值与例外；Understanding 是解释文档。
- [W3C 状态消息解释](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)：不移动焦点的状态变化也需可由辅助技术感知，避免不必要打断。
