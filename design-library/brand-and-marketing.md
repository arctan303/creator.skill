# 品牌、营销与作品展示

> 参考资料，未被项目明确采纳前不生效。用于编写项目自己的设计准则；本模块不构成日常 UI 任务的直接规则，也不授权改写事实主张、增加追踪、发布素材或改变商业承诺。

## 适用边界

- 适用：品牌站、产品落地页、活动入口、作品集、案例研究与以理解价值或形成信任为主的页面。
- 不直接套用：后台表单、数据处理工作台、紧急事务与长篇说明；表达性布局的密度不能泛化到操作区域。
- 同一产品可有表达性的营销页与克制的设置页，共享品牌资产不代表共享同一内容节奏。
- 优先确认观众、真实目标、可信素材与有效主张；“高级”“大胆”等词不足以决定颜色、字体和动效。
- 不把渐变、衬线、圆角、暗色或大标题本身判作好坏；判断它是否服务特定品牌与内容。

## 建立可用的创意约束

1. 确认页面希望访问者理解什么、完成什么，以及哪些主张已经过业务确认。
2. 明确访问者来源与理解程度：初次认识、比较方案、评估专业能力或准备采取行动。
3. 收集有权使用的标识、摄影、案例、字体、作品图和真实产品画面；不能把搜到的素材当成获授权资产。
4. 从现有品牌识别和代表页面中找表达依据，区分稳定身份与一次活动的例外。
5. 确认真实链接、价格、资格、可用地区、联系方式和转化路径；不能为完成视觉稿虚构客户或数据。
6. 核对项目字体、图像、视频、组件和构建约束；优先在已有资产与技术范围内构图。

## 叙事与信息层级的取舍

| 访问者问题 | 可考虑的内容 | 不应自动补齐的模板 |
| --- | --- | --- |
| 这是什么，适合谁 | 明确的价值陈述与有意义的主视觉 | 空泛标语、连续眉题、无信息副标题 |
| 为什么可信 | 可核验案例、产品证据、真实资质 | 虚构用户头像、客户标识、增长百分比 |
| 它怎样解决我的问题 | 真实场景、工作方式、结果与边界 | 三列等高卡片反复讲同一件事 |
| 和我的条件是否匹配 | 有效的范围、费用、资格与限制 | 把所有不利条件推到页脚细字 |
| 下一步是什么 | 与当前意图匹配的明确动作 | 每屏都复制一个无上下文“立即开始” |
| 谁完成了这件作品 | 作者职责、合作范围、过程和结果 | 把团队成果暗示为个人独立完成 |

页面长度来自证据与决策需要；不因为现成模板有 12 个区块就填满 12 个区块，也不为追求首屏极简删掉必要条件。

## 视觉表达与构图

- 先确定内容优先级与主要构图关系，再选择字体角色、对比、留白和媒介，不用随机装饰寻找“设计感”。
- 标题的尺度可以有张力，但长中文、换行和译文仍需可读；不能只在一条短英文标语上成立。
- 字体与色彩从项目身份出发，检查正文、按钮、链接及表单的完整体系；展示字体不必承担所有小字。
- 大面积留白可建立节奏，紧密构图也可符合品牌；两者都要让相关内容的关系可理解。
- 网格可有意打破，但内容顺序与键盘顺序仍合理；不要靠绝对定位把叙事固定在一张桌面截图。
- 主视觉说明产品、作品或情绪中的具体作用；装饰性图形不应挤走关键内容或暗示不存在的功能。
- 产品截图区分真实产品、演示与概念图；不能把未实现界面当作现成功能证据。
- 背景视频、滚动动效和转场只在有表达价值且允许的情况下使用；保持可中断和减少动态效果的体验。
- 图片上的文字对真实明暗和移动裁切进行核查；不能以品牌氛围为由牺牲核心文案可读性。
- 宣传图里的正文尽量保留可选择的真实文本；标志与作品图像另按其用途提供替代说明。

品牌方法可以参考 [IBM Design Language](https://www.ibm.com/design/language/)将字体、摄影、图标与构图组织为体系；采用的是建立一致表达的方法，不是复制 IBM 的网格、字体、蓝色或标识。

## 作品集与案例的内容职责

- 列表帮助浏览不同作品，详情解释目标、背景、约束、贡献与结果；不要把两者都做成只有大图的画廊。
- 项目标题、领域与作者职责可帮助选择；标签只放对判断有用的信息，不用无差别标签云填充视觉。
- 案例结果区分测得数据、客户反馈和作者判断；指标有范围、时间与来源，未知的收益不编造。
- 敏感案例使用已获许可的公开材料或明确脱敏版本；参考库不提供对私人项目的发布授权。
- 图片裁切有利于概览时，详情应提供判断作品所需的完整画面；不能让重要内容永久不可见。
- 外链、下载和联系入口说明实际去向；“查看案例”不能静默变成下载大文件或打开陌生服务。
- 自动轮播不是作品数量多时的默认答案；若使用，需让访问者控制暂停与导航。
- [WAI Carousels](https://www.w3.org/WAI/tutorials/carousels/)支持轮播的键盘操作、焦点及暂停机制；可访问轮播不意味着它必然适合当前叙事。

## 转化、表单与必要后果

- 动作文字表达真实下一步，如预约演示、查看作品或购买；“免费试用”必须符合已确认商业条件。
- 同一页面可重复关键行动，但每次应对应阅读进程，避免连续几屏重复标题、说明和按钮。
- 联系表单只收集任务需要的信息，不能因为模板有公司、电话和预算就擅自全部设必填。
- 隐私、价格、续费、对外提交与不可撤销影响在相关决策位置可获得；减少文案不等于删除后果。
- 不默认加入倒计时、虚构稀缺、诱导同意或营销订阅；实际活动时间和条件必须可核验。
- 不为评估“转化率”默认加埋点、Cookie、指纹或第三方营销 SDK；需要相应产品与隐私授权。
- 重要事实变更由业务确认，设计优化可以重排已确认内容，不能自行扩大承诺。

## 关键状态

| 状态 | 应保留的体验 | 不合适的处理 |
| --- | --- | --- |
| 首屏图片或字体未到 | 内容可读，布局有合理稳定性 | 长时间全屏加载遮挡正文 |
| 视频不可播放或减少动态 | 有静态替代与可用信息 | 主张只藏在必须播放的视频中 |
| 作品缺图或外链失效 | 保留身份、说明和已有下一步 | 一个坏图让整页空白 |
| 联系提交中 | 知道正在提交，避免重复请求 | 按钮无反馈让人连续点击 |
| 提交失败 | 保留允许保留的输入并说明恢复 | 清空表单后显示通用错误 |
| 提交成功 | 真实结果与已确认后续预期 | 未获服务端确认就承诺“已发送” |
| 活动结束或方案不可用 | 当前事实及有效替代入口 | 为维持构图继续展示过期行动 |

## 正反例与例外

- 正例：建筑事务所作品页以空间摄影为主，项目详情说明地点、团队职责与设计约束；联系入口清楚。
- 反例：把所有作品强制改为 SaaS 三列功能卡，加入虚构“效率提升 80%”和与项目无关的渐变图。
- 正例：工业软件落地页用实际工作流和产品截图说明价值，价格与兼容条件在决策位置可见。
- 反例：只留下“重新定义未来”与巨大动画，访问者无法判断产品做什么、是否适合自己。
- 例外：实验艺术作品可故意采用非线性叙事，但要为关键入口和必要内容提供可理解的访问方式。
- 例外：限时活动可突出日期和剩余名额，但必须有真实依据及结束状态，不能伪造紧迫感。
- 例外：成熟品牌可使用极简首页；已有知名度是情境，不代表初创产品也可以省略产品解释。

## 项目化示例

> 范围：一个摄影师的公开作品集。保留已确认的黑白字体系统与原比例作品图，列表按系列浏览。
> 详情展示拍摄主题、个人职责和已授权图片；不虚构客户评价，不为统一高度裁掉关键人物。
> 联系入口沿用现有邮件地址；本次不新增线索表单、追踪脚本或社交账号绑定。
> 例外：展览活动页使用活动色，但不将活动主题替换为全站永久配色。

## 可观察的验收

- 让目标访问者在真实内容下回答产品/作品是什么、适合谁、证据在哪里以及下一步会发生什么。
- 在窄屏、中间宽度、放大及长文案下检查主视觉裁切、标题换行、叙事顺序与行动可达性。
- 关闭动画、模拟缺图与慢字体，确认关键内容仍能读；图片和动效不能成为唯一说明渠道。
- 核对每项数据、评价、客户标识、价格和案例贡献的已确认来源；美观截图不能证明主张真实。
- 用键盘完成浏览、轮播与已有联系流程；实际提交证据与静态原型证据分别说明。
- 检查素材许可及实际部署资源；有本地文件不能证明公开使用权或线上链接有效。
