# 引导、初始化与访问边界

> 参考资料，未被项目明确采纳前不生效。用于编写项目自己的设计准则；本模块不构成日常 UI 任务的直接规则，也不授权新增账号、权限、数据收集或外部集成。

## 适用边界

- 适用：登录、加入组织、连接已有服务、首次初始化、权限请求和第一次进入空工作区。
- 不直接套用：每次进入都重复的欢迎仪式、筛选无结果、服务故障；这些不是同一种“空态”。
- 区分身份认证、组织归属、访问授权、必要设置与可选教学；完成登录不表示已获全部操作权限。
- 一个功能可以无需账号完成；已确认必须认证的功能不能因减少步骤擅自改为公开访问。
- 引导只解释已存在的能力，不借机引入邀请联系人、遥测、通知权限或第三方账号绑定。

## 初始化前确认的事实

1. 用户要完成的首个真实任务是什么，哪些前置条件技术上或业务上确实必需。
2. 当前账号、组织、角色与邀请状态怎样影响可用功能，是否会接触已有的敏感数据。
3. 哪些步骤可以稍后做，哪些是执行前必须确认的费用、数据去向或权限后果。
4. 已有认证方式、恢复路径和管理员工作流是什么；UI 参考不能自行决定安全策略。
5. 初始化是否创建真实资源，能否重复执行，取消、超时或部分失败后留下什么。
6. 核对已有表单、空态、身份入口与反馈组件；先适配已有系统，避免并置两套登录体验。

## 关键决策与取舍

| 决策 | 可考虑的表达 | 边界 |
| --- | --- | --- |
| 是否需要账号 | 只在确需持续身份或数据访问时进入认证 | 不为收集邮箱把可直接完成的任务挡住 |
| 登录与创建账号 | 清楚说明正在使用已有身份还是创建新身份 | 外部单点登录不应伪装成完全站内处理 |
| 初始化步骤 | 按真实依赖顺序分组，少量设置可同页 | 不用虚构步骤制造进度；不可跳过项说明理由 |
| 可选教学 | 在任务现场解释，允许按产品约定跳过 | 不用强制轮播遮住首次真实操作 |
| 权限请求 | 在需要该能力时说明用途和范围 | 不把全部权限预先捆绑成笼统“继续” |
| 邀请和组织选择 | 明确当前组织、邀请对象和实际角色 | 不把加入组织与授予管理员混为一件事 |

账号必要性的参考见 [GOV.UK Create accounts](https://design-system.service.gov.uk/patterns/create-accounts/)。该公共服务模式支持减少不必要门槛，不授权改变本项目已确定的认证边界。

## 登录与访问的表达

- 登录入口展示项目有效的认证方式与组织上下文；不要提供不可用的第三方按钮作为装饰。
- 标签与自动填充语义配合密码管理器；允许项目认证机制支持的粘贴和填充，不以防复制制造负担。
- 创建与输入密码的限制保持可理解并与实际系统一致；不从设计参考擅自修改密码或 MFA 政策。
- 等待验证、验证码重发、外部登录跳转和失败分别反馈；重发频率与有效期来自真实服务。
- 账号枚举风险与错误披露尺度服从既有安全契约；不要以“友好”为由泄露账号是否存在。
- 登录成功后去向与原任务对应；若原目标已失效或无权限，说明事实而非反复跳回登录。
- 会话过期不等同访问被撤销；两者影响的草稿、恢复方式和文案可能不同。
- 敏感操作再次认证只在有效契约要求时出现，不能机械给每次查看套验证。
- [WCAG Accessible Authentication](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html)支持减少记忆、抄写负担及提供辅助机制；不是取消认证的依据。

## 初始化和第一次价值

- 第一屏解释当前要完成的任务与必要前置，不先要求填写与任务无关的完整个人档案。
- 让用户区分真实数据、示例数据与预览；示例不能伪装为已导入或已连接成功。
- 导入或连接前在决策位置说明实际数据范围、目标服务及费用等必要后果，不能藏进可选教学。
- 步骤显示真实完成条件；点击“下一步”不等于后台配置成功。
- 已完成的配置应可核对；允许返回修改到什么程度由数据契约决定，不把返回当重置全部。
- 初始化长任务说明已知阶段或状态；没有可靠进度时不给假百分比和确定倒计时。
- 中断后继续、重试和重新开始遵守已有幂等与持久化行为；不能只靠视觉步骤器承诺恢复能力。
- 可选步骤能按既有契约跳过，并说明以后去哪里处理；必要步骤不伪装为可跳过。
- 成功状态指向能完成首个任务的真实入口；不强迫用户先完成分享、邀请或营销订阅。

## 空态分类

| 原因 | 应表达 | 不应混用 |
| --- | --- | --- |
| 首次没有对象 | 将出现的对象及已有创建/导入方式 | “搜索没有结果” |
| 当前筛选无匹配 | 当前条件、调整或清除条件的方式 | 大幅欢迎插画和“创建第一个” |
| 主动清空后的空集合 | 已完成的动作与当前状态 | 像首次到访一样重新教学 |
| 无权查看 | 允许披露的访问限制及已有申请路径 | 鼓励重复导入相同数据 |
| 正在加载或初始化 | 真实进行中的状态 | “你还没有内容” |
| 请求失败 | 失败范围和可用恢复路径 | 伪造零结果 |
| 部分内容不可用 | 保留可用部分并说明限制 | 整页换成全局空态 |

[Carbon Empty states](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)支持按空态原因提供适当帮助；插图、教学与示例内容是可选工具，不是每个空区域的固定附件。

## 正反例与允许的例外

- 正例：连接资料库前说明将读取哪些目录，成功后显示真实连接对象并进入已有导入任务。
- 反例：一个“开始使用”按钮同时申请通知、上传通讯录、订阅营销并创建公开空间。
- 正例：普通成员无建库权限时，空态提供已有管理员联系路径，仍可使用允许访问的功能。
- 反例：所有无权限情况都显示“创建你的第一个项目”，按钮点击后才告诉用户没有权限。
- 例外：法规或组织策略要求先认证，入口可以直接登录；不能把公共网站的低门槛策略照搬进内网。
- 例外：复杂专业配置需要分步向导；步骤数量不是问题，虚构依赖和强迫无关步骤才是问题。
- 例外：没有恢复能力的初始化允许明确重新开始；不能写“随时回来继续”来掩饰实际状态丢失。
- 例外：受控演示可加载样例，但应标明演示属性，并按已有行为区分与真实项目的关系。

## 项目化示例

假设一个已采用组织单点登录的协作工具，可以形成：

> 范围：受邀成员第一次进入空间。先验证已有组织身份，再展示邀请对应的空间和角色；不新增个人密码。
> 完成加入后直接进入已授权内容。没有内容且有创建权限时展示现有创建入口；没有权限时展示既有联系路径。
> 搜索无匹配保留查询与筛选，不复用首次加入的欢迎页；请求失败显示重试状态。
> 例外：邀请失效时不能先创建空组织作为替代，也不向无权用户暴露空间内容。

采纳条款前确认其与认证和邀请实现一致；界面参考不是扩大权限或改写身份模型的理由。

## 可观察的验收

- 分别用首次用户、已有用户、邀请失效、错误组织和权限不足状态走真实入口。
- 观察用户能否判断“我登录了哪个组织、将获得什么权限、下一步是否创建真实资源”。
- 用密码管理器、粘贴、键盘与已有认证恢复路径完成登录；不能仅检查字段样式。
- 对初始化前、中、后及部分失败状态核对实际资源，检查重试是否造成重复创建或虚假成功。
- 并排检查首次空态、筛选无结果、无权限和失败，下一步必须与原因相符。
- 检查窄屏与放大下必要后果、主要动作和错误反馈；核心信息不能只在图片或悬停里。
- 证据只覆盖实际测试的身份机制；假账号原型不能证明认证安全、授权隔离或外部连接成功。
