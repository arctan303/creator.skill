# 工作台、邮件式布局与编辑器

> 参考资料，未被项目明确采纳前不生效。用于编写项目自己的设计准则；本模块不构成日常 UI 任务的直接规则，也不改变保存、发送、同步或离线契约。

## 适用边界

- 适用：邮件式工作台、工单台、列表与详情联动、文档编辑、草稿创作及需要长时间连续处理的界面。
- 不直接套用：品牌首页、只读手册、一次性短表单；三栏布局不是“专业工具”的必要外观。
- 工作区可同时有导航、对象列表、详情、编辑与辅助信息；首先明确哪个区域正在承担任务。
- 区分查看、选中、编辑、保存、发布、发送；界面相邻不表示这些操作可以合并。
- 不默认新增自动保存、跨页草稿、多端同步、命令面板、快捷键、AI 操作或监控分析。

## 建立上下文

1. 确认使用者一次处理一个对象还是批量分流，是否需要持续参照其他材料。
2. 列出对象归属、当前选择、未读/已处理状态、草稿与实际服务端状态分别由谁维护。
3. 核实现有保存时机、取消含义、发送后果、并发冲突与导航中断的处理。
4. 阅读共用 Shell、列表、编辑器、工具栏、分隔拖拽与反馈组件，保留项目已确定的密度和视觉语言。
5. 选择代表性任务：从列表打开、阅读、编辑、保存或发送、处理失败，再继续下一个对象。

## 工作区布局的取舍

| 情境 | 可考虑的布局 | 需要验证的边界 |
| --- | --- | --- |
| 在同一集合高频切换对象 | 列表与详情并置 | 当前对象明显，列表滚动与详情滚动关系可理解 |
| 编辑必须参照来源 | 编辑区与参照区并置 | 不能把正文压到无法输入；不默认增加新浮窗 |
| 单个复杂编辑任务 | 编辑优先的独立页面 | 回到来源时保留原有上下文契约 |
| 窄屏无法同时容纳多栏 | 列表、详情分步进入 | 返回路径、选中对象和未保存状态保持一致 |
| 可选元信息或辅助工具 | 按需展开的侧区 | 核心收件人、费用、权限等必要信息不能藏进去 |
| 多种对象共用外壳 | 稳定导航与任务区 | 避免每个模块都建立不同的全局操作位置 |

[Carbon UI shell](https://www.carbondesignsystem.com/building-blocks/core/components/ui-shell-left-panel/guidelines)提供外壳与可选导航的职责参考；其层数、数量阈值和样式属于该体系，不直接升级为项目要求。

## 邮件式工作台与对象操作

- 导航定位集合，列表定位对象，详情定位当前内容；不要让三处都叫“当前”却指不同范围。
- 未读、选中、焦点、已归档和同步中分别表达，颜色之外有可理解的文本或语义。
- 列表提供完成分流必需的发件人、主题、时间或状态，不为了短卡片截掉所有判断依据。
- 行内快捷动作可减少切换，但不能只在悬停可用；触控和键盘有等价入口。
- 批量工具栏显示对象数量与操作范围；打开详情与勾选批量对象不混为同一个动作。
- 处理一个对象后列表是否自动移到下一个，沿用有效契约；不能因“提升效率”擅自改为自动跳转。
- 详情刷新保留可用内容，并说明异步状态；后台请求不应无故抢走编辑焦点或阅读位置。
- 全局搜索、集合筛选和正文查找是不同范围；既有入口的提示与结果要说明正在找哪里。

## 草稿与保存语义

- 清楚区分“未修改”“已修改”“保存中”“已保存”“保存失败”；状态由真实写入结果驱动。
- 自动保存如果已有明确契约，可在不打断输入的位置反馈；不能把仅写入本地称作已同步。
- 手动保存保留可理解的保存与取消边界；原位编辑不意味着删除保存按钮或取消能力。
- 保存失败保留可修复内容，说明哪些操作仍可用；重试不得悄悄覆盖较新的服务端版本。
- 草稿保存与发送/发布分开，最终操作旁保留收件对象、公开范围及不可撤回后果中必要的信息。
- 重复提交防护不能只靠按钮灰掉；请求结果未知时不要引导用户随意重复发送。
- 附件上传、格式处理与正文保存若是不同状态，分别反馈；不能用一个“已完成”掩盖失败附件。
- 多人协作、版本比较和离线恢复只有在产品已支持时设计；参考建议不构成新增依赖的理由。

## 快捷键、焦点与中断

- 先保证可发现的按钮、菜单和键盘操作，再考虑已有快捷键的展示；快捷键不能成为唯一入口。
- 文本输入、中文输入法合成、浏览器和辅助技术快捷键需要避让；输入字母不得意外归档邮件。
- 若采用纯字符快捷键，按 [WCAG 2.1.4](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html)提供关闭、改键或只在组件获焦时生效的合适机制。
- 工具栏若采用 [APG Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/)模式，应一起实现其焦点管理；不能只添加 role。
- 当前光标、文字选择与滚动位置属于编辑上下文；不相关刷新不能无故重建整个编辑器。
- 导航、切换对象、关闭窗口、会话过期和断网是不同中断；按实际草稿契约处理，不给所有中断套同一确认框。
- 有未保存内容且离开会丢失时，说明具体影响和可选动作；没有变更不反复拦截正常导航。
- 恢复草稿需要标明来源和时间等必要依据；无法恢复时不能以“稍后继续”承诺不存在的能力。
- 新通知与后台状态不抢焦点；真正阻止当前任务的问题才在对应位置要求处理。

## 关键状态

| 状态 | 可观察表现 | 应避免 |
| --- | --- | --- |
| 未选择对象 | 列表可用，详情解释当前区域 | 自动假选一个敏感对象 |
| 对象加载失败 | 保留列表与对象身份，给已有重试路径 | 把失败当“该集合无记录” |
| 草稿修改后切换 | 遵守保存/丢弃/保留的既有契约 | 静默丢失或擅自永久保存 |
| 发送结果未知 | 说明尚未确认，提供已有核对路径 | 宣称失败后允许无限重复发送 |
| 版本冲突 | 展示冲突事实与现有处理选择 | 后台以旧草稿覆盖新内容 |
| 权限中途失效 | 限制对应操作并处理草稿影响 | 清空编辑器后只弹一个通用错误 |
| 批量部分成功 | 分项或范围明确，剩余项可继续处理 | 用绿色总提示掩盖失败对象 |

## 正反例与例外

- 正例：邮件工作台中，行焦点、勾选和当前详情独立；快捷归档后按既有规则更新列表并保留可追踪焦点。
- 反例：给一切交互绑定单字母，用户在中文输入或语音输入时意外触发删除。
- 正例：编辑器显示真实保存状态，权限失效保留允许保留的草稿并说明后续限制。
- 反例：为“清爽”删除保存区，只在失焦时提交；用户以为取消能撤销，实际上已写入。
- 例外：代码编辑器可具有密集工具栏与面板；密度来自专业任务，不宜套为所有产品的默认。
- 例外：一次性审批可使用独立详情页，不因参考邮件客户端而引入三栏和拖拽分隔。
- 例外：高风险发送或发布保留必要确认和后果说明；减少中断不能取消有效门禁。

## 项目化示例

> 范围：已有工单工作台。桌面保留列表与详情；窄屏依次打开，返回时保留现有集合条件。
> 回复草稿继续手动保存；保存失败保留文字。发送按钮说明对象，发送请求未知时显示现有核对入口。
> 本次只统一工具栏与焦点，不新增自动保存、全局快捷键或离线存储；批量处理维持原作用范围。
> 例外：长表单转独立编辑页，不能因全站布局一致而压入窄抽屉。

## 可观察的验收

- 用实际长主题、长正文和多个附件，完成选中、阅读、编辑、保存或发送的授权路径。
- 检查输入法、键盘导航、工具栏与已存在快捷键；输入字符不能触发无关对象操作。
- 在草稿未保存时覆盖切换、返回、断网和权限过期中项目已支持的状态，核对真实保留与丢失边界。
- 在宽屏、中间宽度、窄屏与放大下检查各栏最小可用宽度、滚动归属及编辑区是否被固定工具遮住。
- 模拟实际保存与发送失败，核对状态文案和真实服务端结果；静态截图不能证明草稿恢复或未重复提交。
