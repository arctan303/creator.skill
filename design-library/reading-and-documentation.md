# 阅读、文档与知识导航

> 参考资料，未被项目明确采纳前不生效。用于编写项目自己的设计准则；本模块不构成日常 UI 任务的直接规则，也不声明现有页面已合规。

## 适用边界

- 适用：产品手册、帮助中心、技术文档、政策长文、知识库与以理解内容为主的详情页。
- 不直接套用：频繁处理对象的工作台、视觉作品浏览、短促交易表单；分别考虑对应模块。
- 同一网站的首页可能承担推广，正文承担阅读；页面用途决定取舍，不给整个仓库贴单一风格标签。
- 改进阅读不自动授权全文搜索、收藏、阅读历史、账号、分析追踪或新的内容服务。
- 来源提供结构和可访问性依据；下列组合、示例与验收方式是参考库的综合建议。

## 先明确读者怎样使用内容

1. 区分首次学习、快速查一个参数、逐步执行和核查原始依据；它们需要不同的入口与结构。
2. 列出读者真实知道的词汇与要找的答案，用内容样本检查分类名称，避免只沿团队组织架构导航。
3. 确认版本、语言、适用平台和时效是否会改变答案；必要的适用条件进入正文开头。
4. 核对已有内容模型、文章模板、标题层级、代码块、目录、图片、链接和共享排版角色。
5. 确认支持的窄屏、放大、打印与离线能力；保留已有契约，不把所有候选能力一次引入。

## 结构与导航的决策

| 情境 | 可考虑的表达 | 代价与边界 |
| --- | --- | --- |
| 从多个主题寻找答案 | 分组索引、清楚的章节导航 | 分类应有可理解的区分，避免很多只有一页的空分组 |
| 一篇包含多个可独立查阅的段落 | 页内目录和稳定标题锚点 | 短文不必固定占据一栏；锚点不能被固定页头遮住 |
| 需要理解文档所在层级 | 面包屑 | 它表达内容层级；不能用来假装线性任务进度 |
| 按顺序完成操作 | 编号步骤、前置条件、完成判据 | 不能仅给“下一页”而隐去会改变操作的条件 |
| 少数人需要的补充说明 | 可展开的详情 | 大多数人必读的风险、资格、费用不藏在里面 |
| 多个版本并存 | 明确当前版本与切换范围 | 切换到不对应的页面时说明去向，不能静默换成最新版答案 |

面包屑的用途与局限可参照 [GOV.UK Breadcrumbs](https://design-system.service.gov.uk/components/breadcrumbs/)；可选补充说明可参照 [GOV.UK Details](https://design-system.service.gov.uk/components/details/)。这些组件的品牌样式和实现包不随原则一起引入。

## 长内容的排版与信息顺序

- 标题先告诉读者主题；导语补充适用范围或关键结论，不复述标题三次。
- 用语义标题表达嵌套关系，用文字角色控制外观；不能因字号选择把正文伪装成标题。
- 正文行长、字号和行距需要一起检验；宽屏可限制正文宽度，表格与代码可以有独立宽度策略。
- 中英文混排、数字、链接和代码使用项目已有字体回退；不因英文样张漂亮便替换中文正文字体。
- 段落承担一个连贯意思；仅并列或操作顺序才用列表，避免每句话都变成碎片。
- 复杂条件先给共同路径，再就近解释例外；不能为追求短文隐藏执行前必须知道的后果。
- 注释、图注、时间和版本降低视觉权重时仍可读；引用与脚注应能回到原来的阅读位置。
- 链接文字说明目标，正文颜色之外保留可识别的链接表达；不把所有链接命名为“了解更多”。
- 代码块保留复制后的完整语义，展示语言与必要运行条件；不能为适应窄屏删掉影响结果的参数。
- 横向滚动只限制在确需二维展示的代码或表格容器；普通正文不跟着撑出页面。
- 图片说明承担图中无法直接理解的上下文；信息图提供对应文字内容，装饰图不制造冗余播报。
- 不默认用选项卡或折叠组件切碎整篇文档；跨段比较、浏览器查找、链接分享都可能受影响。

标题结构依据 [GOV.UK Headings](https://design-system.service.gov.uk/styles/headings/)；页面区域与辅助导航依据 [WAI Page Structure](https://www.w3.org/WAI/tutorials/page-structure/)。具体字体、行长与目录位置由项目内容和品牌决定。

## 关键状态

| 状态 | 读者需要看到 | 不合适的处理 |
| --- | --- | --- |
| 文章加载中 | 可理解的加载反馈及稳定布局 | 先显示别篇文章内容再替换 |
| 图片或示例失败 | 说明缺失部分，保留能读的正文 | 一张图片失败让整篇变空白 |
| 链接失效或内容移除 | 事实、可用上级入口或替代内容 | 未说明就把所有旧地址跳到首页 |
| 搜索没有结果 | 当前查询与调整方法 | 冒充“知识库尚无内容”并引导创建 |
| 旧版或弃用内容 | 适用版本、替代去向和必要迁移影响 | 淡化成无法识别的小灰字 |
| 无阅读权限 | 沿用项目披露策略；允许用通用未找到响应隐藏资源存在性，允许披露时提供既有访问路径 | 泄露受限资源存在性，或把权限问题错误解释为用户筛选错误 |
| 页面内跳转 | 目标标题可见，地址与阅读位置对应 | 只有滚动动效，键盘和辅助技术失去定位 |

## 正反例与允许的例外

- 正例：部署手册先列运行环境和数据迁移影响，再按执行顺序展开；版本导航与页内目录职责分明。
- 反例：每一段都放进带阴影的卡片，卡片前重复标题、摘要与“详细说明”，打断连续阅读。
- 正例：API 参考保留参数表和可复制示例；复杂示例能横向滚动，正文仍在窄屏重排。
- 反例：为了整齐截断所有参数值、代码和完整来源，读者无法核验实际请求。
- 例外：艺术评论可用较大的引文、跨栏图和表达性标题；仍保留阅读顺序与链接可识别性。
- 例外：法规原文需要精确段号和稳定引用；不要以“口语化”改掉法定术语或重排引用编号。
- 例外：极短帮助页只有一个主题时，可没有目录、侧栏、面包屑组合；直接进入内容更清楚。
- 例外：故意保持旧版视觉的归档页可独立存在，但需让读者知道版本和历史性质。

## 项目化示例：把建议变成有限条款

假设一个已有静态手册站，读者经常从错误信息直达具体解决方案，可形成以下候选：

> 范围：故障排查文章。开头展示适用产品版本、症状和修复前的数据影响；正文沿“诊断 → 处理 → 验证”组织。
> 页面沿用现有正文与代码组件；超过多个独立章节时使用已有页内目录，不新增搜索服务。
> 固定页头下的锚点必须能露出完整标题；无对应版本文章时明确说明，提供可识别的替代链接。
> 例外：发行说明保留按版本排列，不强制改成故障排查模板。

采纳前用真实短文、长文和旧版文档试排；记录实际采纳的范围、例外和来源，不能把整段参考复制成全站命令。

## 可观察的验收

- 让不熟悉目录的人从主题入口找到一项真实答案，观察分类与标题是否让其误入其他主题。
- 从外部深链接打开长文中段；目标标题、适用版本和正文关系都能确认。
- 只用键盘跳过重复导航，进入正文、访问页内目录与链接，并能追踪可见焦点。
- 在窄屏、放大和长中文标题下查看正文、目录、脚注、图片与代码；检查固定元素是否遮挡内容。
- 在真实图表、长 URL、缺图、旧版与无结果状态中检查信息是否完整；不能只使用短英文占位文。
- 使用阅读器的标题与区域导航，检查层级和名称；标题字号相同不能证明语义正确。
- 比较改前改后的同一阅读任务，说明减少了何种定位困难；截图仅证明可见布局，不能证明内容准确。
- 若项目支持打印，检查分页、链接文本与代码截断；无该契约时不自行增加打印产品能力。

## 来源与采用说明

核实日期：2026-11-11。官方页面可能更新；采纳具体组件能力时重新核对项目版本。

- [GOV.UK Headings](https://design-system.service.gov.uk/styles/headings/)：支持语义标题与一致的结构；GOV.UK 字体和样式不是所有项目的要求。
- [GOV.UK Breadcrumbs](https://design-system.service.gov.uk/components/breadcrumbs/)：支持层级定位及平坦结构、线性流程中的不适用边界。
- [GOV.UK Details](https://design-system.service.gov.uk/components/details/)：支持按需展开少数人需要的说明，不支持隐藏多数读者的必要信息。
- [WAI Page Structure](https://www.w3.org/WAI/tutorials/page-structure/)：支持区域、标题和内容结构的可访问定位；不是具体三栏布局标准。
- [WAI Images](https://www.w3.org/WAI/tutorials/images/)：支持按图片用途提供文字替代；不能靠文件名证明替代文本质量。
