### 两组、隔离与记录

- 每例 A/B **各至少3次**，每次全新会话、独立仓库 `git init`，任务/素材/工具/模型/时间预算相同，仅工作流包不同；交错随机安排顺序，保存随机化表。模型用 `gpt-6.1-sol` high；先核实宿主实际解析的 ID，不静默换模型。无跨次记忆、子代理、网络资料或实时外部服务。
- 运行根拟为系统临时目录下 `creator-eval-<run-id>/work/<case>/<group>/<repeat>`，解析后的绝对路径须位于当前源码仓库之外。每次有独立初始 Git commit；恢复例另保存预置未提交差异及 hashes。临时结果先保留，不运行完即删除。
- 仅模型可见项目副本挂给执行进程；隐藏测试、参考补丁、评分标准、run map、宿主原始日志放**另一个控制目录**，执行者无读取权限。目录放外面不等于隔离；先验证 ACL/独立运行身份或容器边界，不满足就不开始正式采样。隐藏测试在被评对象进程结束后由控制进程运行，不能把含答案文件复制回被评仓库。
- A/B 使用同一干净宿主配置；排除个人/祖先 AGENTS、全局 creator/其他技能、插件、hooks、记忆和自定义指令泄漏。项目自己的设计/产品资料两组相同。认证按宿主支持方式提供，不复制整个个人配置，不把凭据交给被测命令。需要不可得的隔离/认证能力时记录阻断，不以危险绕过选项解决。
- runner 在模型工作区外保存 `codex exec --json` 原始 JSONL、stderr、CLI/模型版本、会话 ID、时间、token usage、命令/工具输入输出、退出码、完整最终 diff/文件摘要及测试输出。禁止代理自己生成“执行记录”。长输出需落盘并有摘要，截断即标证据缺口。

### 独立评分与失败归因

用例/规则作者 A 不做结果裁判。另选未写用例或规则的评分代理 G（6.1 Sol high，新会话、只读）先审 oracle 的正确/错误校准材料，再按冻结 rubric 评分；主会话只汇总并核对证据。预先随机匿名编号，尽可能隐藏组别；轨迹中的技能路径可能揭示组别，不声称完全盲评。

## 5. 删减：先冻结标准，再运行

- 单位是一整个有边界的章节；一次只测一个候选。预先写待删章节、理由、会影响哪些用例、不可改变的事实和成功/失败判据。用户选定产品机制、发布/隐私/权限边界不参与删减；未知来源先保留。
- 同义重复直接合并到一个规范来源并保留条件链接，不削弱含义、不等待“证明重复有害”。这类编辑独立留痕和结构/引用检查，不能与方法新增混成一个不明差异；进入后续候选快照时明列。
- D 组使用同一冻结任务、隐藏测试、rubric 和资源条件，每个启用用例至少3次；与该章节所属的父版本 P 比较。若 P 已有同基线证据可复用；如 P 是刚补过方法的 C 且缺完整成绩，先补 P 相关缺失运行，不能把删减效果与方法收益混算。
- 接受删减的必要条件：**没有新增硬边界失败；每例完成/恢复/证据通过数不低于父版本；未增加原本没有的无谓追问或重复动作；正文实际减少且适用引用仍完整**。成本中位数仅辅助；减少验证造成省 token 不算收益。任何回退保留章节；证据不确定先保留，不反复抽样直到通过。
- 第一闭环最多提出一个方法补丁和一个删减候选；若 B 无对应缺口就不添加方法，若没有可安全删章节就不凑删除。研究性结论不改写为长期效果保证。
